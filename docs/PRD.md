## 2. 产品概述

### 2.1 背景与痛点

JSONL (JSON Lines) 广泛应用于大模型训练集、系统日志和轻量级大数据存储。然而，当前市面上的可视化工具存在以下致命痛点：

1. **大文件卡死：** 动辄数百 MB 或 GB 级别的 JSONL 文件让传统编辑器或主流 Web 应用直接 OOM（内存溢出）。
2. **异构结构对齐难：** JSONL 每行的字段（Key）不一定完全一致，且嵌套层次深，缺乏直观的扁平化矩阵表格展示。
3. **隐私合规风险：** 现有的线上工具大多需要用户上传文件到服务器解析，对于企业敏感的业务日志或专有 AI 训练集存在严重的安全风险。

### 2.2 产品定位

一款**全网最快、100% 隐私安全、基于强类型路由**的纯前端 JSONL 矩阵可视化工具。利用 Rust WASM 的极致速度在浏览器后台线程进行零垃圾回收（GC）卡顿的流式解析，并利用 TanStack 生态在 React 19 下实现千万级行的丝滑虚拟化滚动与全状态 URL 同步。

## 3. 技术架构设计

本产品采用 **Client-Centric 全栈解耦架构**。为了保证浏览器主线程的绝对流畅（60 FPS），核心计算与渲染完全分离：

```
                    [ 浏览器/用户输入层 ]
                              │ (本地拖拽 / 远程 URL)
                              ▼
┌──────────────────────────────────────────────────────────────┐
│                  TanStack Start 核心宿主环境                 │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 1. 强类型路由状态层 (TanStack Router)                  │  │
│  │    └─ URL 实时映射: `?page=1&filters=status%3D200`      │  │
│  └──────────────────────────┬─────────────────────────────┘  │
│                             │                                │
│                             ▼ [按需驱动数据加载]             │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 2. 智能异步数据缓存 (TanStack Query)                    │  │
│  │    └─ 统一调度并缓存已解析的数据分片，支持跨页预加载    │  │
│  └──────────────────────────┬─────────────────────────────┘  │
│                             │                                │
│                             ▼ [传递清洗后的结构化矩阵]       │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ 3. 极致视图层 (TanStack Table + Virtual v3)            │  │
│  │    └─ React 19 自动编译优化，DOM 树永远只保持几十行      │  │
│  └────────────────────────────────────────────────────────┘  │
└─────────────────────────────┬────────────────────────────────┘
                              │
                              │ (postMessage 异步二进制通道)
                              ▼
┌──────────────────────────────────────────────────────────────┐
│             浏览器后台线程 (Web Worker + Rust WASM)          │
│  - 接收原始文件流 (File Stream)，不占用主线程内存            │
│  - 扫描换行符 `\n`，在内存中仅建立字节偏移量索引表           │
│  - 动态计算并增量合并全量 JSON Key (Schema Matrix 提取)       │
│  - 根据主线程视窗请求，使用 `file.slice` 做到真正的按需解析  │
└──────────────────────────────────────────────────────────────┘

```

## 4. 核心功能需求 (Functional Requirements)

### 4.1 数据双模加载与多线程解析 (Data Loading & Parsing)

* **本地隐私模式 (Local-First):**
* 用户通过拖拽或文件选择器导入本地 `.jsonl` / `.json` 文件。
* 前端通过流式 API (`File.stream()`) 将数据分块（Chunk）喂给 Web Worker 中的 Rust。
* **禁止任何服务器上传行为**，确保数据 100% 留存在用户本地。


* **远程流式模式 (Remote-Streaming):**
* 支持输入线上 JSONL URL。借助 TanStack Start 的 **Server Functions** 或前端 `fetch` 建立流式代理，边下载边在后台解析。


* **Rust 字节级索引扫描：**
* Rust 后端不一次性把文本转为 JS 对象。而是快速扫描 `\n`，生成行索引表：`Index -> (start_byte, length)`。
* 在扫描的同时，利用增量并集算法自动对复杂的嵌套 JSON 进行扁平化提取（例如 `{"a":{"b":1}}` 自动提取为表头 `a.b`）。



### 4.2 路由级强类型状态管理 (URL-as-State)

* **状态完全 URL 化：** 表格的当前分页 (`page`)、每页条数 (`size`)、当前隐藏的列 (`hiddenColumns`)、列排序 (`sort`) 以及搜索过滤条件 (`filters`)，必须实时、安全地同步在浏览器 URL 路径中。
* **类型安全验证：** 采用 TanStack Router 的 `validateSearch` 机制，配合 `Zod` 进行运行时参数校验。即使用户手动在浏览器地址栏输入错误的参数，系统也能自动纠错（如：输入 `page=abc` 自动纠正为 `page=1`），拒绝页面崩溃。

### 4.3 智能动态矩阵表格 (Dynamic Smart Grid)

* **异构数据自动对齐：** 如果某一行缺失了全局表头中的某个 Key，TanStack Table 必须自动将其单元格渲染为灰色的 `null` 或 `undefined`。
* **虚拟滚动渲染：** 使用 **TanStack Virtual v3** 驱动视图。无论文件包含 1 万行还是 1000 万行，页面内真实的 HTML `<tr>/<div>` 节点数恒定在 $30 \sim 50$ 个。
* **数据预加载 (Prefetching)：** 当用户浏览第 $N$ 页时，**TanStack Query** 会自动在后台提前向 Rust Worker 请求第 $N+1$ 和 $N+2$ 页的数据。当用户滚动向下时，实现“零延迟零白屏”体验。

### 4.4 丰富的数据交互与详情抽屉 (UX & Interactions)

* **动态表头控制：** 提供左侧/右侧固定侧边栏，列出全局提取出的所有字段，支持通过复选框一键控制表格列的显示与隐藏。
* **列宽动态拉伸：** 允许用户拖拽表头调整列宽，双击自适应内容。
* **单行 JSON Tree 视图：** 点击表格任意行，右侧滑出 Drawer（抽屉），使用树状着色视图展示该行未扁平化前的完整原始 JSON 对象，并提供“一键复制单行”和“格式化”功能。

### 4.5 局部损坏容错 (Fault Tolerance)

* **脏数据隔离：** 当大文件中夹杂了非法 JSON 格式（如截断、乱码）时，Rust 解析器不能崩溃。应跳过该行或将其标记为 `Error Row`，并在前端表格对应行中以红底高亮显示，提示“该行 JSON 格式损坏”，点击可在抽屉内查看损坏的原始文本。

## 5. UI/UX 设计规范

> 详细设计规范请参阅 **[UI_UX_SPEC.md](./UI_UX_SPEC.md)**。

本产品 UI 对标 **DataGrip、TablePlus、Supabase Table Editor、Prisma Studio** 等成熟 SQL 数据表格管理工具，采用「三栏 + 工具栏 + 状态栏」IDE 级布局，核心要点：

* **数据区等宽字体 (Monospace)** — 保证数字与代码列对齐可读。
* **亮色/暗色双主题** — 默认跟随系统偏好，支持手动切换。
* **单元格类型感知渲染** — 数字右对齐、布尔值彩色徽标、null 灰色斜体、嵌套对象折叠徽标。
* **行号列 + 斑马纹 + Hover 高亮 + 选中竖线指示器** — 专业数据表格标准配置。
* **列菜单 (排序/筛选/隐藏/固定) + 列宽拖拽 + 列重排** — 灵活的列交互。
* **右侧详情抽屉** — JSON 语法着色树状视图，可折叠嵌套节点。
* **键盘快捷键** — 支持 Vim 风格导航与 DataGrip 式快捷操作。
* **空状态引导页** — 拖拽上传区域的友好引导。

## 6. 非功能性需求与性能指标 (Non-Functional Requirements)

### 6.1 极致性能指标 (KPIs)

* **首屏首开时间：** 1GB 大小的本地 `.jsonl` 文件拖入后，**$\le 300\text{ms}$** 内必须在界面展示出总行数和表头，使用户可以开始操作。
* **运行帧率 (FPS)：** 在高频、快速滚动虚拟表格时，主线程渲染帧率必须稳定在 **$60\text{fps}$**（由 React 19 Compiler 消除不必要的组件重绘提供支持）。
* **内存基线占用：** 无论处理的文件体量是 10MB 还是 2GB，因采用分片按需解析（On-Demand Slice Fetching）和 TanStack Query 的自动 GC 淘汰机制，浏览器 Tab 页面的峰值内存占用必须 **$\le 150\text{MB}$**。

### 6.2 兼容性与部署

* **环境要求：** 兼容所有支持 WebAssembly、Web Workers 和 File API 的现代浏览器（Chrome、Edge、Safari、Firefox 最新版）。
* **静态部署：** 项目通过 TanStack Start 配置为 **SSG (静态站点生成)** 编译。打包产物仅包含一个 HTML、一个 JS、一个 CSS 和一个 `.wasm` 二进制文件。可免费部署在 GitHub Pages、Cloudflare Pages 或 Vercel，**无任何服务器及带宽续费成本**。

## 7. 模块划分与开发路线图 (Phase Roadmap)

### Phase 1: Rust 核心解析器与 WASM 编译 (第 1-2 周)

* 搭建 Rust 2024 工程，引入 `serde_json` / `simd-json`。
* 编写换行符扫描器、字节偏移量索引生成逻辑。
* 实现自适应异构 JSON 的“最大并集扁平化表头提取”算法。
* 利用 `wasm-bindgen` 导出接口，并在 Web Worker 中跑通独立测试。

### Phase 2: TanStack Start 骨架与强类型路由 (第 3 周)

* 初始化 TanStack Start 工程，配置 React 19 与 Tailwind CSS v4.0。
* 设计 `/` 与 `/viewer` 路由文件，使用 Zod 完成 Search Params 的强类型绑定。
* 搭建 Web Worker 通信桥梁，实现主线程与后台 Rust 之间的二进制（ArrayBuffer）流式数据拉取。

### Phase 3: 表格虚拟化与数据缓存集成 (第 4-5 周)

* 引入 `@tanstack/react-table` 管理动态列模型，实现列的显示、隐藏与拉伸。
* 引入 `@tanstack/react-virtual` 结合 Tailwind 绝对定位实现百万行级虚拟滚动。
* 引入 `@tanstack/react-query` 建立分页缓存与预加载机制，完成数据链闭环。

### Phase 4: 细化 UI 与发布验收 (第 6 周)

* 开发右侧详情抽屉（JSON 树状查看器）以及局部坏行报错高亮提示。
* 在 Windows (Edge/Chrome)、Mac (Safari/Chrome) 环境下进行 2GB 级别大文件压测，排除内存泄漏。
* 静态编译，一键发布部署至生产环境。
